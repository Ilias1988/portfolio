# Ilias1988 Portfolio

Static cybersecurity portfolio and Hack The Box Machines, Challenges and Sherlocks write-up knowledge base built with Astro.

## Local development

```powershell
npm install
npm run dev
```

Production validation:

```powershell
npm run check
npm run build
npm run preview
```

## Publishing a write-up

1. Confirm that the Hack The Box content is officially publishable. "Expired" is not the same as "retired".
2. Select the template that matches the content type:

   - Machines: `templates/writeup-template.md`
   - Challenges: `templates/challenge-writeup-template.md`
   - Sherlocks: `templates/sherlock-writeup-template.md`

3. Copy it to the appropriate content path, for example:

   `src/content/writeups/hackthebox/machines/machine-name.md`

   `src/content/writeups/hackthebox/challenges/web/challenge-name.md`

   `src/content/writeups/hackthebox/sherlocks/dfir/sherlock-name.md`

4. Use a lowercase URL-safe filename. The directory path becomes the public URL:

   `/writeups/hackthebox/machines/machine-name/`

5. Store screenshots under a matching path, for example:

   `public/images/writeups/hackthebox/machines/machine-name/`

6. For Challenges, set `challengeCategory`. For Sherlocks, set `sherlockCategory`. The content schema validates the supported HTB categories.
7. Remove flags, task answers, personal secrets, VPN data, private keys and unrelated sensitive metadata. Retired lab credentials may appear only when they are essential to reproduce the documented path.
8. Do not redistribute original Challenge or Sherlock investigation packages.
9. Run `npm run check` and `npm run build` before committing.

Active-content drafts must not be stored in this public repository, even with `draft: true`. Keep them locally outside the repository or in a private repository until publication is permitted.

## SEO

- Canonical metadata and social metadata are generated by the shared layouts.
- The site generates a sitemap index plus separate page and write-up sitemaps with accurate `lastmod` values during every build.
- Crawlable collection pages are available at `/writeups/machines/`, `/writeups/challenges/` and `/writeups/sherlocks/`.
- Empty collection pages automatically use `noindex` and stay out of the sitemap until their first public entry is added.
- `robots.txt` points crawlers to the sitemap index.
- `/rss.xml` is generated from the public write-up collection.
- Each write-up outputs Google-compatible `BlogPosting` structured data, retains its `TechArticle` classification and includes breadcrumb structured data.

## Deployment

The repository includes a GitHub Pages workflow. It does nothing locally and only runs after the changes are pushed to `main` and GitHub Pages is configured to use GitHub Actions.
